# Bump Version & Publish

Source of truth is `src/`. `bb-contents.js` / `.min.js` / `.map` are generated by
`npm run build` — never hand-edit them.

## Step 1 — Decide the new version

Follow semver:
- **Patch** `1.1.x` → bug fix, no new attribute
- **Minor** `1.x.0` → new module or new attribute
- **Major** `x.0.0` → breaking change

## Step 2 — Update the version in the 2 source places

Both must be identical before building.

| File | Location | Example |
|---|---|---|
| `package.json` | `"version": "..."` | `"version": "1.1.22"` |
| `src/core.js` | `const BB_CONTENTS_VERSION = '...'` (~line 11) | `'1.1.22'` |

> The `@version` banner in `bb-contents.js` is **generated** by `build.js` from
> `package.json` — do not edit it by hand.

## Step 3 — Build

```bash
npm run build
```

This regenerates `bb-contents.js`, `bb-contents.min.js`, and `.min.js.map` with the
new version banner.

## Step 4 — Commit the version bump + rebuilt bundles

```bash
git add package.json src/core.js bb-contents.js bb-contents.min.js bb-contents.min.js.map
git commit -m "chore: bump version to X.X.X"
```

## Step 5 — Publish (choose target)

### develop / test release

```bash
git push origin develop
npm publish --tag test
```

Consumers install with: `npm install @bebranded/bb-contents@test`

### main / live release

```bash
git push origin main
npm publish
```

Consumers install with: `npm install @bebranded/bb-contents@latest`

## Checklist

- [ ] Version identical in `package.json` and `src/core.js`
- [ ] `npm run build` run; regenerated bundles staged
- [ ] `git status` is clean before publishing
- [ ] Correct branch checked out (`develop` or `main`)
- [ ] `npm publish` uses correct tag (`--tag test` or omit for latest)
- [ ] Verify on jsDelivr CDN after publish: `https://cdn.jsdelivr.net/npm/@bebranded/bb-contents@X.X.X/bb-contents.js`
